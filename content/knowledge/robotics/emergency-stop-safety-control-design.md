> 출처 확인 범위: 이 노트는 EU 법령 본문(지침 2006/42/EC 의 부속서 I 1.2절, 규정 (EU) 2023/1230 의 대응 조항)을 EUR-Lex 에서 직접 읽은 내용만 근거로 한다. **IEC 60204-1(정지 범주), ISO 13850(비상 정지), ISO 13849-1(PL), IEC 62061(SIL), IEC 61508, 안전 PLC 제품 문서는 유료이거나 접근하지 못해 읽지 않았으며, 그 조항·정지 범주 번호·성능 수준 값은 이 노트에 쓰지 않았다.** 법령 요건은 해석 문서와 정합 표준을 통해 충족을 입증하므로 실제 설계는 해당 표준 원문과 인증 기관 지침을 따른다. EU 이외 지역(미국 등)의 규정은 다루지 않는다. 법적 조언이 아니다.

## 문제

로봇 개발자는 "비상 정지 버튼이 눌리면 `cmd_vel` 을 0 으로 낸다" 를 비상 정지로 착각하기 쉽다. 그 코드가 죽거나, 네트워크가 끊기거나, 틀린 명령을 낼 때 정지가 보장되지 않는다. 법령은 정지 기능 자체의 요건과 제어 시스템의 고장 허용을 별도로 규정한다.

## 법령이 요구하는 것

### 정지 종류 (지침 부속서 I 1.2.4)

| 종류 | 요지 |
| --- | --- |
| 정상 정지(1.2.4.1) | 기계를 안전하게 완전히 멈추는 제어 장치가 있어야 한다. 작업 위치마다 정지 장치가 필요하고, **정지 제어는 시동 제어보다 우선**한다. 멈춘 뒤에는 구동기 에너지 공급을 차단한다. |
| 운전 정지(1.2.4.2) | 운전상 구동기에 에너지를 유지하며 멈춰야 하면, 그 정지 상태가 **감시되고 유지**되어야 한다. |
| 비상 정지(1.2.4.3) | 실제 또는 임박한 위험을 피하기 위한 하나 이상의 장치. |

### 비상 정지 장치의 요건 (1.2.4.3)

- 제어 장치가 명확히 식별되고, 잘 보이고, 빠르게 접근 가능해야 한다.
- 추가 위험을 만들지 않고 위험한 공정을 가능한 한 빨리 멈춘다. 필요하면 안전 동작을 일으키거나 허용한다.
- **래치**: 작동을 멈춘 뒤에도 정지 명령은 장치가 계속 눌려 있음으로써 유지되고, 해제는 적절한 조작으로만 가능하다. 장치를 작동시키면서 정지 명령을 안 내는 것은 불가능해야 한다.
- **해제가 곧 재시동이 아니다.** 해제는 재시동을 허용할 뿐이다.
- 운전 모드에 관계없이 항상 작동 가능해야 한다.
- 다른 보호 수단의 **백업**이지 **대체** 가 아니다.
- 예외: 정지 시간을 줄이지 못하거나 필요한 특수 조치를 취하게 하지 못하는 기계, 휴대용 수동·수동 유도 기계. 즉 모든 기계에 필수는 아니고 위험 저감 효과를 따져 판단한다.
- 연동된 기계는 비상 정지가 관련 장비까지 멈출 수 있게 조립되어야 한다(1.2.4.4).
- 운전 모드 선택은 비상 정지를 제외한 모든 모드보다 우선한다(1.2.5).

### 제어 시스템 요건 (1.2.1, 1.2.6)

- 제어 시스템의 하드웨어·소프트웨어 고장이나 논리 오류가 위험 상황으로 이어지면 안 된다.
- 기계가 예기치 않게 시동하면 안 되고, **이미 정지 명령이 내려졌다면 정지를 막지 말아야** 한다. 이동 부품은 자동이든 수동이든 정지가 방해받지 않아야 한다.
- 무선 제어는 올바른 제어 신호가 오지 않으면(통신 두절 포함) 자동으로 정지해야 한다(해당 요건의 정확한 조항 귀속은 확인하지 못함).
- 전원이 끊기거나 복귀되거나 변동해도 위험 상황이 생기면 안 되고, 예기치 않은 시동이 없어야 한다.

### 규정 2023/1230 과의 관계

규정 (EU) 2023/1230 은 지침 2006/42/EC 를 **2027년 1월 14일부터** 폐지하고 같은 날부터 적용된다(제51조, 제54조; 일부 조항은 더 이른 날짜 적용). 경과 조치와 제품별 적용 시점은 읽지 않았다. 규정 본문의 비상 정지 조항(부속서 III 1.2.4.3)은 지침과 같은 요건을 "machinery or related product" 로 확대해 쓴다. 규정은 또한 외부 기기·원격 장치의 연결이 위험 상황을 만들지 않아야 하고, 안전 준수에 핵심인 소프트웨어·데이터를 우연한 또는 의도적 변조로부터 보호하고 개입 증거를 수집하라는 요건을 포함한다. 네트워크 로봇에서는 보안이 곧 안전 요건이라는 뜻이다([위협 모델링](/develop-wiki/knowledge/security/threat-modeling-stride/)).

## 소프트웨어 설계에 주는 함의

1. **비상 정지는 일반 제어 소프트웨어의 바깥에 둔다.** 법령은 소프트웨어 고장이 위험으로 이어지지 않아야 한다고 요구한다. ROS 노드나 [행동 트리](/develop-wiki/knowledge/robotics/behavior-tree-vs-state-machine/) 위에서 정지를 구현하면 그 요건을 충족한다고 말할 수 없다. 정지는 독립 경로(하드웨어 회로나 인증된 안전 장치)가 수행하고, 소프트웨어는 상태를 관찰해 표시·복구 절차를 돕는다.
2. **정지 명령은 시동보다 우선하고 유지된다.** 아래 래치 로직처럼 해제와 시작을 분리한다.
3. **통신이 끊기면 정지 쪽으로 간다(fail-safe).** 무선 제어는 신호 소실 시 자동 정지가 요건이다. 유선·네트워크 구간도 같은 원칙으로 감시 주기를 둔다([DDS 지연](/develop-wiki/knowledge/robotics/realtime-dds-latency/)).
4. 정지 후 구동기를 어떻게 둘지(에너지 차단, 감시된 정지 유지, 브레이크)는 정상 정지·운전 정지·비상 정지의 의미가 다르므로 위험 평가로 정한다. 힘 제어 로봇은 정지 중 외력에 의한 이동을 별도로 고려한다([임피던스 제어](/develop-wiki/knowledge/robotics/impedance-admittance-force-control/)).

```ts
// 비상 정지 래치의 요건을 흉내 낸 상태 기계(교육용, 인증 가능한 안전 기능이 아님)
type State = 'RUN_PERMITTED' | 'STOPPED_LATCHED' | 'RESET_DONE';
class EStopLatch {
  state: State = 'RUN_PERMITTED';
  press() { this.state = 'STOPPED_LATCHED'; }
  reset() { if (this.state === 'STOPPED_LATCHED') this.state = 'RESET_DONE'; } // 해제 = 재시동 "허용"
  start(): boolean { if (this.state === 'RESET_DONE') this.state = 'RUN_PERMITTED'; return this.state === 'RUN_PERMITTED'; }
  get driveEnabled() { return this.state === 'RUN_PERMITTED'; }
}
```

(실행해 확인: 누르면 구동 불가, 버튼을 놓아도 불가, reset 만으로도 불가, 별도 start 후에만 가능했다.)

## 안전 PLC 에 대해

안전 PLC·안전 릴레이·안전 등급 드라이브가 비상 정지와 감시 기능을 수행한다는 구조는 [산업 로봇 안전](/develop-wiki/knowledge/robotics/robot-safety-iso-10218/) 노트에서 해설 기사를 근거로 다뤘다. 이 노트는 안전 PLC 의 내부 구조(이중 채널, 상호 감시, 진단 범위)와 인증 수준을 1차 출처로 확인하지 못했으므로 서술하지 않는다.

## 언제 쓰나

- 로봇·AMR·셀을 EU 시장에 낼 때 비상 정지와 제어 시스템 요건을 설계 초기에 정하기 위해.
- 소프트웨어 팀이 "정지" 라는 말이 가리키는 기능이 서로 다른 것임을 맞출 때(정상·운전·비상).

## 주의/비용

- 법령은 목표를 정하고, 충족 방법(성능 수준, 회로 구조)은 표준에 있다. 이 노트만으로 적합성을 주장할 수 없다.
- 비상 정지는 **보호 방호의 대체가 아니다.** 사람이 위험 구역에 들어가는 상황은 울타리, 광 커튼, 속도·거리 감시 같은 보호 수단이 먼저이고 비상 정지는 그 백업이다.
- 비상 정지가 오히려 추가 위험(낙하, 관성 이동)을 만들 수 있어 정지 방법을 위험 평가로 정해야 한다. 법령도 "추가 위험 없이" 를 요구한다.
- 규정 시행(2027-01-14) 전후로 적용 법령이 바뀌므로 제품 출시 시점의 적용 문서를 확인한다.
- 모바일 로봇(AMR/AGV)·서비스 로봇·차량에는 별도의 적용 표준이 있을 수 있다. 여기서는 확인하지 않았다.
