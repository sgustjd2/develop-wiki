쿼션트 필터의 구조와 XOR 필터와의 비교는 [쿼션트·XOR 필터](/develop-wiki/knowledge/algorithms/quotient-xor-filter/)에 있고, 크기를 조절하지 못하는 변형은 [벡터 쿼션트 필터](/develop-wiki/knowledge/algorithms/vector-quotient-filter/)에 있다. 그 노트들이 "리사이즈·병합이 된다/안 된다"를 한 줄로 언급한 부분을 **어떻게 되고, 어디까지 되는지** 풀어 쓴다.

## 문제

- 블룸 필터는 처음에 항목 수를 예측해 크기를 정한다. 예측이 틀리면 오탐률이 커지고, 비트 배열은 해시 위치만 남아 원래 값을 복원할 수 없어서 **다시 만들려면 원본 키 전체를 다시 읽어야** 한다. 같은 크기의 블룸 필터끼리의 OR 병합만 쉽다.
- 필터를 쓰는 곳(LSM 트리의 SSTable 필터, 쓰기를 모았다가 합치는 구조)은 작은 필터를 많이 만들어 나중에 합치거나, 커지는 집합에 맞춰 키워야 한다. 키를 다시 읽을 수 없는 경우도 많다.

## 해법

### 원리: 지문이 정렬 순서로 복원된다

Bender 등의 논문은 쿼션트 필터에서 **삽입된 지문의 다중집합을 정확히 복원**할 수 있고, 슬롯을 선형으로 훑으면 지문을 정렬된 순서로 순회할 수 있다고 설명한다. 이 두 성질이 리사이즈와 병합을 가능하게 한다. 지문 `f` 는 상위 `q` 비트(몫, 슬롯 위치)와 하위 `r` 비트(나머지, 슬롯에 저장)로 나뉜다. 전체 길이 `p = q + r` 이다.

### 리사이즈: 나머지 한 비트를 몫으로

논문은 해시 테이블과 달리 **재해시 없이** 나머지의 한 비트를 몫으로 빌려 오거나 되돌려 확장·축소할 수 있다고 설명한다. 구현은 기존 슬롯을 훑으면서 지문을 새 배열에 복사하는 것이다.

- 확장: `(q, r) → (q+1, r−1)`. 슬롯 수가 2배가 되고, 슬롯당 저장하는 나머지가 한 비트 줄어든다. 지문 `p` 는 그대로다.
- 축소: 반대 방향. 비트를 나머지로 되돌린다.

```ts
// 지문의 논리 내용을 정렬 배열로 둔 모델: 리사이즈는 지문을 그대로 두고 (q, r) 만 바꾼다
grow(): QF { const o = new QF(this.q + 1, this.r - 1); o.fps = this.fps.slice(); return o; }
```

### 병합: 병합 정렬

두 필터를 순회하면 지문이 정렬돼 나오므로, 병합 정렬의 병합 단계처럼 두 입력을 한 번 훑으며 출력 필터에 순차로 쓴다. 논문은 이를 캐시 친화적이라고 한다(순차 읽기·쓰기). SSD 용 cascade filter 는 이 병합을 이용해 여러 크기의 필터를 합친다(그림 5).

```ts
static merge(a: QF, b: QF): QF {           // 같은 (q, r) 이어야 한다
  if (a.q !== b.q || a.r !== b.r) throw new Error('지문 형식이 다르면 병합 불가');
  const o = new QF(a.q + 1, a.r - 1);       // 슬롯 2배로 합침
  let i = 0, j = 0;
  while (i < a.fps.length || j < b.fps.length)
    o.fps.push(j >= b.fps.length || (i < a.fps.length && a.fps[i] <= b.fps[j]) ? a.fps[i++] : b.fps[j++]);
  return o;
}
```

### 한계: 지문 비트 수는 늘지 않는다 (직접 확인)

지문 `p` 비트는 키에서 한 번 해시해 얻은 값이라, 필터에는 그 이상의 정보가 없다. 따라서 오탐률은 대략 `항목 수 / 2^p` 로 정해지고, 키우는 동안 `p` 가 고정이라 **같은 항목 수에서는 오탐률이 변하지 않지만 담을 수 있는 항목이 늘어나는 만큼 오탐률도 따라 오른다.** 리사이즈를 반복할수록 나머지 `r` 이 줄어 결국 0 이 되면 더는 키울 수 없다.

지문의 논리 내용만 정렬 배열로 둔 모델(슬롯 배치·메타데이터 비트는 생략)을 직접 실행해 확인했다(`p = 20`, 항목 1,500개).

| 단계 | (q, r) | 거짓 음성 | 오탐률 실측 |
| --- | --- | --- | --- |
| 시작 | (12, 8) | - | 1.42e-3 (이론 N/2^p = 1.43e-3) |
| 확장 3번 후 | (15, 5) | 0 | 1.42e-3 (변화 없음) |
| 같은 형식 두 필터 병합(각 1,500개) | (13, 7) | 0 | 2.96e-3 (항목 2배 → 오탐률 약 2배) |
| 형식이 다른 필터 병합 | - | 오류로 거부 | - |

이 결과가 의미하는 바: 리사이즈는 **적재율을 낮추려고** 쓸 때 유효하고, 항목이 크게 늘어나도 오탐률을 유지하려면 `p` 를 늘려 다시 만들어야 하며 그러려면 원본 키가 필요하다. 이 해석은 논문의 서술과 직접 실험에서 이끌어 낸 것이다(논문이 이 한계를 이런 식으로 표현하지는 않는다).

## 언제 쓰나

- 원본 키를 다시 읽기 어렵거나 비싼 상황에서 필터를 **한 번쯤** 늘리거나 줄여야 할 때.
- 작은 필터를 쓰기 경로에 쌓았다가 주기적으로 합치는 구조(LSM, 로그 구조 색인, 캐스케이드 필터).
- 삭제가 필요하고 정렬된 순회가 필요한 경우. 블룸 필터는 삭제에 4배 공간이 든다고 논문이 언급한다.

## 주의·비용

- **p 가 고정**이라 키울수록 오탐률 한계가 올라간다. 시작할 때 목표 최대 규모와 오탐률로 `p` 를 정한다.
- 병합 입력은 같은 해시 함수와 같은 지문 길이를 써야 한다. 시드·`p` 가 다르면 병합이 의미 없다.
- 병합은 최대 적재율(논문 예시는 3/4)을 넘지 않게 출력 크기를 정해야 한다. 쿼션트 필터는 적재율이 높아지면 클러스터가 길어져 느려진다.
- 리사이즈·병합은 전체 순회를 하므로 O(n) 이다. 한 번에 수행하면 지연 스파이크가 생긴다. 두 단계로 나눠 점진적으로 하는 설계가 필요할 수 있다(설계 권고).
- 벡터 쿼션트 필터는 이 기능이 없다. 리사이즈·병합이 필요하면 선택지에서 빠진다.
- 이후 연구에서 리사이즈 때 오탐률을 유지하려는 변형이 나왔을 수 있다. 이 노트는 확인하지 않았다.
