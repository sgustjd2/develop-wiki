## 개요

모형은 배포하면 끝이 아니다. 학습 때 본 세계와 운영 중의 세계가 달라지면 성능이 떨어진다. 그래서 운영 단계는 (1) 전개(배포)와 활용 시나리오, (2) 모니터링(성능·입력 분포·예측), (3) 문제가 감지되면 재학습·재설계(리모델링)의 순환이다. 핵심 개념은 **드리프트**: 시간이 지나며 데이터 또는 데이터와 정답의 관계가 바뀌는 현상이다. 이 노트는 어떤 변화가 어떤 지표에 잡히고 안 잡히는지를 구분해 준다.

## 시험 범위 대응

빅데이터분석기사 4과목 "분석결과 해석 및 활용 → 활용(분석모형 전개, 활용 시나리오 개발, 모니터링, 리모델링)" 과 "분석모형 평가 및 개선" 에 대응한다. 공식 범위는 항목명뿐이라 아래 절차 설명은 Google MLOps 문서와 필자 정리에 기반하며 수험 교재의 단계 구분과 다를 수 있다. PSI·드리프트 용어는 공식 범위에 직접 항목이 없다.

## 핵심 용어

| 한국어 | 영어 | 정의 |
| --- | --- | --- |
| 전개(배포) | deployment | 학습한 모형을 실제 업무 시스템에서 예측에 쓰도록 올리는 일 |
| 활용 시나리오 | usage scenario | 모형 출력을 누가 어떤 업무·의사결정에 어떻게 쓰는지 정한 계획 |
| 모니터링 | monitoring | 운영 중 성능·입력 분포·예측 결과를 지속적으로 관찰 |
| 리모델링 | remodeling, retraining | 성능 저하 시 데이터·변수·모형을 다시 구성하고 학습 |
| 데이터 드리프트 | data drift (covariate shift) | 입력 X 의 분포가 변함. 정답과의 관계는 그대로일 수 있음 |
| 개념 드리프트 | concept drift | 입력과 목표 변수의 관계가 시간에 따라 변함(Gama 등 2014) |
| 훈련-서빙 편향 | training-serving skew | 학습 때와 운영 때 모형이 받는 특성이 다른 것 |
| PSI | population stability index | 기준 분포와 현재 분포를 구간별 비율로 비교한 안정성 지표 |
| 재학습 트리거 | retraining trigger | 재학습을 시작하는 조건 |

"drift" 용어는 문헌마다 범위가 달라 어떤 글은 데이터 드리프트와 개념 드리프트를 구별 없이 쓴다. 이 노트는 위 표처럼 구분한다.

## 전개·활용 시나리오·모니터링·리모델링

필자가 정리한 순서이며 단계명은 고정된 표준이 아니다.

1. **활용 시나리오**: 모형 결과를 쓰는 업무, 사용 주기(실시간/배치), 임계값과 후속 조치, 모형이 틀렸을 때의 대안을 정한다.
2. **전개**: 모형·전처리·변수 정의를 함께 배포한다. 학습과 운영의 전처리가 다르면 훈련-서빙 편향이 생긴다(Google 문서: 특성 저장소가 같은 정의를 학습·서빙에 제공해 줄인다). 새 모형은 카나리 배포나 A/B 시험으로 일부 트래픽에 먼저 적용하는 방법이 있다(Google 문서의 해당 서술은 이번에 원문 대조하지 못했다).
3. **모니터링**: Google 문서는 (a) 운영 중 모형 성능, (b) 입력 데이터·특성의 통계적 성질, (c) 기록된 예측과 행동의 변화를 본다고 한다.
4. **리모델링**: 아래 트리거가 충족되면 재학습하거나 변수·모형 구조를 다시 설계한다.

**MLOps 성숙도**(Google 문서): 수준 0 은 모든 단계가 수작업(노트북→엔지니어 인계), 수준 1 은 학습 파이프라인 자동화와 지속 학습(데이터·모형 검증, 트리거, 메타데이터), 수준 2 는 파이프라인 코드의 CI/CD 까지 자동화.

**재학습 트리거**(Google 문서): 수시(수동), 일정 주기(일·주·월), 새 데이터 도착, 성능 저하, 데이터(분포) 드리프트. Google 문서는 입력 분포가 크게 변해 모형이 낡았을 때의 트리거를 'concept drift' 라 부르며, 이 노트의 구분으로는 데이터 드리프트에 해당한다. 주기는 데이터 변화 속도와 재학습 비용으로 정한다. 데이터 검증에서 스키마 편향(예상 밖·누락·형식 오류 특성)은 파이프라인을 멈추고 조사하며, 값 편향(통계 성질 변화)은 재학습을 일으킬 수 있다고 한다.

**기술 부채**(Sculley 등 2015, NIPS): 머신러닝은 빠르게 만들기 쉽지만 장기 유지 비용이 크다는 논문이다. 초록이 나열하는 위험: 경계 침식, 얽힌 의존성, 숨은 피드백 루프, 미공개 하위 사용자, 취약한 데이터 의존성, 설정 문제, 외부 세계의 변화 등. 모형 코드보다 주변 인프라 관리가 부담이라는 요지다(본문은 읽지 못함).

## 드리프트의 종류

- **정의**: 개념 드리프트는 온라인 지도학습에서 입력과 목표 변수의 관계가 시간에 따라 바뀌는 것이다(Gama 등 2014, ACM Computing Surveys 46(4), 초록). 이 서베이는 적응 학습의 과정, 대응 전략의 분류, 대표 기법, 평가 방법을 다룬다.
- **실제(real) vs 가상(virtual) 드리프트**: 흔히 조건부 분포 P(y∣X) 가 바뀌는 것(실제)과 입력 분포 P(X) 만 바뀌는 것(가상 = 공변량 이동)으로 구분한다. 이 구분과 변화 양상(급격·점진·점증·재발)은 Gama 서베이 본문이 아니라 후속 문헌 검색 요약으로만 확인했다(미확인 — 아래 검증 범위).
- 데이터 드리프트는 성능에 영향이 없을 수도 있고(입력만 달라지고 규칙은 동일), 개념 드리프트는 **입력 분포가 그대로여도** 성능을 떨어뜨린다. 그래서 입력 분포 지표와 성능 지표를 **둘 다** 본다.

## PSI

`PSI = Σ_j (p̂_j − p_0j) · ln(p̂_j / p_0j)` (p_0j: 기준(개발 시) 분포의 구간 j 비율, p̂_j: 현재 비율, B 구간). Potgieter 등(arXiv 2307.11878)은 이 식을 쓰고 PSI 가 대칭화한 쿨백-라이블러 발산(Jeffreys 발산)의 일치 추정량이라고 설명한다.

- 구간은 보통 기준 분포의 분위수(10분위 등)로 정한다. 비율이 0 인 구간은 로그가 정의되지 않아 식에 지시함수를 두거나 작은 값을 더해 처리한다(구현마다 다름).
- **0.1 / 0.25 기준은 관례**다. 위 논문은 이를 Lewis(1994)에서 비롯해 널리 쓰이는 경험칙("Lewis constants")으로 설명한다: 0.10 미만은 조치 불필요, 0.10~0.25 는 추가 조사, 0.25 초과는 큰 변화로 모형 재구축 고려. 표본 크기·구간 수·표본 변동을 고려하지 않아 임의적이라는 비판이 있으며, 표본이 작으면 불필요한 재구축이, 크면 과소 반응이 나타난다고 한다. Yurdakul(2018 학위논문)도 PSI 의 통계적 성질 연구가 적고 임계값이 근거 없이 쓰인다고 지적한다(초록 요약 확인, 본문 미확인).
- 적용 대상: 입력 특성, 모형 점수(예측 확률) 분포.

## 헷갈리는 구분

| 쌍 | 구분 |
| --- | --- |
| 데이터 드리프트 vs 개념 드리프트 | 입력 분포 변화 vs 입력→정답 관계 변화. PSI 는 앞쪽만 잡는다 |
| 드리프트 vs 이상치 | 일부 이상 값 vs 분포·관계가 지속적으로 이동 |
| 모니터링 vs 평가 | 모니터링은 운영 중 지속 관찰. 정답이 늦게 오면 성능 대신 입력·예측 분포를 대리 지표로 씀 |
| 재학습 vs 리모델링 | 같은 구조·새 데이터로 다시 학습 / 변수·알고리즘까지 재설계(구분은 필자 정리, 수험서마다 다를 수 있음) |
| 훈련-서빙 편향 vs 드리프트 | 편향은 같은 시점 파이프라인 불일치(버그), 드리프트는 시간에 따른 세계 변화 |

## 직접 계산

Python 3.15, numpy 2.5.5, scikit-learn 1.9.1, seed 고정(값은 seed 의존).

- **식 검산**: 기준 (0.5, 0.3, 0.2), 현재 (0.4, 0.3, 0.3) → 항별 0.02231, 0, 0.04055, PSI 0.06286. 같은 값이 `Σ p ln(p/p0) + Σ p0 ln(p0/p)` (대칭 KL)와 일치.
- **분포 이동**: 기준 표준정규 1만 개, 10분위 구간, 현재 1만 개. 평균이 0, 0.1, 0.25, 0.5, 1.0 이동하면 PSI 0.0012, 0.0105, 0.0547, 0.2291, 0.9212. 표준편차 1.5 배는 0.1907.
- **표본 크기와 무변화 PSI**: 같은 분포에서 뽑은 현재 표본 크기 100 → PSI 평균 0.097 이고 300 회 중 44% 가 0.1 초과(드리프트 없는데 관례상 "조사" 구간), 500 → 평균 0.020 (0.1 초과 0%), 1만 → 0.0028. 표본이 작으면 관례 임계값이 부적절할 수 있음을 보여 준다.
- **데이터 vs 개념 드리프트**(로지스틱 회귀, 특성 2개, 정답 규칙 `x1 + x2 + 노이즈 > 0`): 드리프트 없음 정확도 0.937. 입력 평균만 이동(규칙 동일): x1 의 PSI 1.983 로 매우 크지만 정확도 0.949 로 **저하 없음**. 규칙을 `x1 − x2` 로 바꾸되 입력 분포는 그대로(개념 드리프트): x1·x2 의 PSI 0.004·0.002, 모형 점수 PSI 0.005 로 **PSI 는 정상인데 정확도 0.506** 으로 무작위 수준. 새 규칙 데이터로 재학습하면 0.931 로 회복.
- 이 시뮬레이션은 선형 경계의 합성 데이터이며 현실의 일반 결론이 아니라 두 드리프트의 구분을 보이는 예다.

## 언제 쓰나 / 주의

- 정답(라벨)이 늦게 도착하는 업무(대출 부실, 이탈)는 입력·점수 분포(PSI)로 먼저 경보하고, 라벨이 오면 성능을 직접 계산한다.
- 입력 분포 경보와 성능 저하는 별개다. 둘 다 점검하고, 경보 시 데이터 파이프라인 오류(스키마·결측 급증)부터 의심한다 → [데이터 품질](/develop-wiki/knowledge/data-analytics/data-quality-privacy-deidentification/).
- 재학습은 검증 절차를 같이 자동화하지 않으면 나쁜 모형이 배포될 수 있다(Google 문서의 모형 검증: 기준 모형과 비교, 구간별 성능, 서빙 호환성, 카나리·A/B). 재학습 시 평가 누수 주의 → [데이터 분할·누수](/develop-wiki/knowledge/machine-learning/data-split-cross-validation-leakage/).
- 예측 자체가 미래 데이터를 바꾸는 피드백 루프(추천·승인 모형)는 모니터링 지표가 오염된다(Sculley 초록의 "숨은 피드백 루프").
- 임계값(0.1/0.25)은 관례이므로 자기 데이터의 정상 변동(표본 크기별 PSI 분포)을 먼저 측정해 정한다. 설명 가능성 점검은 [모형 해석](/develop-wiki/knowledge/machine-learning/model-interpretation-feature-importance-shap-pdp/).

## 검증 범위

- 읽은 것: Google Cloud MLOps 아키텍처 문서(수준 0~2, 모니터링, 트리거, 검증, 훈련-서빙 편향), Sculley 등 2015 NeurIPS 초록 페이지, Gama 등 2014 초록(TU/e 연구 포털), Potgieter 등 arXiv 2307.11878 HTML(PSI 식·Lewis 상수에 대한 서술), Yurdakul 학위논문 검색 요약.
- **읽지 못함**: Gama 서베이 본문(ACM 403, 대학 저장소 차단) — real/virtual 구분과 변화 양상은 후속 문헌의 검색 요약 수준이며 본문 대조 안 함. Sculley 본문, Lewis(1994) 원문, 신용평가 교재의 PSI 정의 원문, Yurdakul 본문.
- 전개·활용 시나리오 개발·리모델링의 공식 절차 정의는 공개 1차 출처 미확인. 위 절은 필자 정리.
- 실행한 것: PSI 식·시뮬레이션(numpy, sklearn). 실행 안 함: 실제 모니터링 도구, 드리프트 탐지 알고리즘(DDM·ADWIN 등은 다루지 않음).
