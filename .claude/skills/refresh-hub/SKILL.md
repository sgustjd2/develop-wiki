# 허브 정기 업데이트

## 1. 대상 선정
1. `research/log/` 파일명으로 카테고리별 마지막 survey 날짜를 구한다. 로그가 없으면 "미조사".
2. 우선순위:
   - 미조사 카테고리
   - `models/*`, `ai/*` 는 30일, `frontend/*`, `backend/*` 는 90일, `knowledge/*` 는 180일 경과
   - 항목 수가 3개 미만인 카테고리
3. 한 번에 **최대 6개** 카테고리. 사용자가 범위를 지정하면 그에 따른다.

## 2. 실행
- 선정 목록과 이유를 사용자에게 한 줄씩 보여 준다.
- 서로 다른 영역의 카테고리는 각 담당 에이전트를 **병렬로** 띄워 `survey-category` 절차 1~2단계를 수행하게 한다. 같은 영역끼리는 파일 충돌을 피하려고 한 에이전트가 순서대로 처리한다.
- 모두 끝나면 바뀐 파일 전체를 `fact-checker` 하나에 넘기고, 모델이 바뀌었으면 `model-taxonomist` 로 전체 일관성 점검.

## 3. 마무리
- `npm run validate && npm run build`
- 카테고리별 로그 작성(`survey-category` 4단계 형식)
- 사용자 보고: 카테고리별 추가/수정/폐기 후보 수, 사람 결정이 필요한 항목.
