> 출처 메모: VINS-Mono 논문(Qin, Li, Shen, arXiv 1708.03852)의 서론·관련 연구·IV(사전적분)·V(추정기 초기화)절 본문을 읽었다. 초기화 방법의 원전으로 인용되는 Martinelli 의 닫힌 해와 Kaiser 외의 자이로 바이어스 동시 보정, ORB-SLAM 기반 초기화(Mur-Artal 외)는 읽지 못했고 VINS-Mono 가 그것들을 어떻게 요약하는지만 옮긴다. 관측성의 엄밀한 증명은 읽지 않았다. 아래 수치는 직접 만든 선형 모형의 실험이다.

## 문제

단안 카메라는 이동량을 **스케일 불명** 으로만 알려 준다. IMU 는 미터 단위 가속·각속도를 주지만 바이어스가 있고 중력이 섞여 있다. 두 센서를 하나의 비선형 최적화([사전적분](/develop-wiki/knowledge/robotics/imu-preintegration/)된 IMU 인자 + 시각 재투영 인자)로 합치려면 시작 값이 필요하다. 시작 값이 나쁘면 최적화가 수렴하지 않는다. 논문은 초기화를 단안 VINS 에서 "가장 부서지기 쉬운 단계" 라 부르고, **정지 상태에서 시작한다고 가정**하는 것은 이동 중 시작하는 실제 사용에 맞지 않는다고 한다.

## 해법: 시각 먼저, IMU 정렬

VINS-Mono 는 느슨한 결합으로 초기값을 얻는다. 시각만으로 구조를 세운 뒤, 미터 단위의 IMU 사전적분을 거기에 맞춰 스케일·중력·속도·바이어스를 풀고, 그 결과를 강결합 최적화에 넘긴다.

1. **시각만의 SfM(슬라이딩 윈도).** 최신 프레임과 윈도 안 어떤 프레임 사이에 추적 특징이 30개 넘고 회전을 보상한 시차가 20픽셀을 넘으면 five-point 로 상대 회전·스케일 불명 이동을 구하고, 스케일을 임의로 잡아 삼각측량한 뒤 나머지 프레임은 PnP, 마지막에 전체 번들 조정을 한다. 기준 좌표계는 첫 카메라 프레임 `c0` 이다. 조건이 안 되면 기다린다.
2. **자이로 바이어스.** 이웃 프레임 쌍마다 SfM 의 상대 회전과 자이로 사전적분 회전 `γ` 의 차이를 최소화한다. `γ` 를 바이어스에 대한 1차 근사로 쓰므로 **바이어스 `δb_w` 의 선형 최소제곱** 이 된다. 풀고 나면 모든 사전적분을 새 바이어스로 다시 전파한다.
3. **속도·중력·스케일.** 미지수는 `X_I = [v_0, ..., v_n, g^{c0}, s]`(각 프레임의 body 속도, `c0` 좌표의 중력, 스케일)다. 이웃 프레임마다 위치 사전적분 `α` 와 속도 사전적분 `β` 가 `s`·`g`·`v` 에 **선형**이라, 제약을 쌓아 `min ||ẑ - H X_I||²` 를 푼다. 카메라-IMU 외부 파라미터(회전 `q_c^b`, 이동 `p_c^b`)가 대략이라도 필요하다.
4. **중력 정제.** 중력 크기를 아는 값(약 9.81 m/s²)으로 고정하면 방향 2자유도만 남는다. 현재 추정 방향 `ĝ` 의 접평면 기저 `b1, b2` 를 잡고 `g = 9.81·ĝ + w1·b1 + w2·b2` 로 놓아 `w1, w2` 를 다른 상태와 함께 풀기를 수렴할 때까지 반복한다.
5. **세계 좌표로.** 중력을 z 축에 맞추도록 `c0 → w` 회전을 구해 모든 상태를 회전하고, SfM 이동을 미터로 환산한다.

논문이 가속도계 바이어스를 **일부러 초기화에서 뺀** 점에 주의한다. 중력이 플랫폼 동역학보다 훨씬 크고 초기화 구간이 짧아 가속도계 바이어스는 중력과 결합되어 관측하기 어렵다는 이유다(별도 분석을 인용). 그 값은 이후 강결합 최적화가 추정한다.

중력 접평면 기저를 만드는 부분은 짧아서 직접 옮겨 둔다(논문의 알고리즘 1 과 같은 아이디어를 TypeScript 로 새로 쓴 것이다).

```ts
type V3 = [number, number, number];
const cross = (a: V3, b: V3): V3 => [a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0]];
const unit = (a: V3): V3 => { const n = Math.hypot(...a); return [a[0]/n, a[1]/n, a[2]/n]; };

/** g = G*ĝ + w1*b1 + w2*b2 로 크기를 고정한 중력의 2자유도 파라미터화에 쓰는 기저 */
export function tangentBasis(g: V3): [V3, V3] {
  const ghat = unit(g);
  const axis: V3 = ghat[0] === 1 && ghat[1] === 0 && ghat[2] === 0 ? [0, 0, 1] : [1, 0, 0];
  const b1 = unit(cross(ghat, axis));
  return [b1, cross(ghat, b1)];
}
```

(`b1·b2 = 0`, `b1·ĝ = 0`, `|b2| = 1` 임을 임의의 중력 벡터로 실행해 확인했다.)

## 관측성: 언제 스케일이 풀리는가

논문의 서론이 핵심 문장을 준다. 단안 VINS 는 **가속도의 자극(excitation)** 이 있어야 미터 스케일이 관측된다. 그래서 정지·등속 직선 상태에서 시작할 수 없고, 알 수 없는 이동 상태에서 출발해야 한다. 한편 중력 때문에 롤·피치는 관측되고, 전역에서 관측되지 않는 것은 **3차원 이동과 중력 둘레의 회전(요)의 4자유도** 라고 쓴다(루프 폐쇄를 4자유도 포즈 그래프로 하는 근거).

이 직관을 직접 만든 선형 모형으로 확인했다. 위 3번 단계의 선형 시스템(회전 없이 R=I, 카메라=IMU, 노이즈·바이어스 없음)을 그대로 만들어 21 프레임(간격 0.1 s, 총 2 s), 참 스케일 `s = 2.5` 로 풀었다.

| 운동 | 최소 특이값 | 복원된 스케일 | 복원된 중력 |
| --- | --- | --- | --- |
| 등속(가속 0) | 2.4e-15 (영공간 존재) | 0 (최소 노름 해, 참값 2.5 아님) | (0, 0, -9.81) 정확 |
| 가속이 있는 운동 | 0.023 | 2.500 | (0, 0, -9.81) 정확 |

등속에서는 `s` 를 키우고 모든 속도를 같은 양의 상수만큼 옮겨도 모든 제약이 그대로라 해가 하나로 안 정해진다. 중력은 속도 사전적분 제약 쪽에서 풀리므로 이 경우에도 복원된다(중력 크기를 고정하지 않은 모형). 가속이 있어도 최소 특이값이 0.02 로 작아, 노이즈가 있으면 스케일이 약하게만 관측된다는 것도 읽을 수 있다. 이 모형은 회전·바이어스·노이즈를 뺐으므로 실제 정확도를 말해 주는 것은 아니다.

## 언제 쓰나

- 단안(또는 스케일 모호한) 카메라 + IMU 로 VIO 를 새로 띄우거나 **추적을 잃은 뒤 재시작** 할 때. 논문은 같은 초기화 모듈을 실패 복구에도 쓴다.
- 스테레오·RGB-D 는 스케일이 이미 알려져 있어 이 절차의 스케일 항이 필요 없다(일반론, 이 논문의 범위 밖).
- 파라미터(`s`, `g`, `v`, `b_w`)가 선형 풀이로 나오므로 비선형 반복 전의 **좋은 초기점** 이 목적이지 최종 정확도가 목적이 아니다.

## 주의/비용

- **움직임이 필요하다.** 시작 직후 사용자에게 흔들어 달라고 하는 UX 가 흔한 이유다. 위 모형처럼 등속이면 스케일이 풀리지 않는다. 가속이 아주 작으면 스케일이 부정확한 채 최적화로 넘어간다.
- **외부 파라미터에 의존.** 카메라-IMU 외부 파라미터가 많이 틀리면 정렬이 틀린다. 논문은 이를 온라인으로 보정하는 장치를 따로 둔다.
- **느슨한 결합의 한계.** 시각 SfM 이 먼저 성립해야 한다. 특징이 부족하거나 시차가 모자라면 시작 자체가 안 된다. 순수 회전이나 극단적 원거리 장면은 이 조건을 못 채운다(일반론).
- **중력 크기를 안다고 가정.** 단위·위치(고도·위도)에 따라 달라지는 값을 고정한다.
- **가속도계 바이어스를 무시한 시작.** 시작 직후 한동안 바이어스 오차가 가속도에 섞여 들어간다. 이후 강결합 단계에서 줄어드는지는 환경에 따라 다르다.
- **스케일 수렴 시간.** VINS-Mono 는 관련 연구로 ORB-SLAM 기반 초기화에서 스케일 수렴에 10초 이상 걸릴 수 있다는 보고를 소개한다. 빠른 초기 스케일이 필요한 응용에서는 이 점이 걸림돌이다.
