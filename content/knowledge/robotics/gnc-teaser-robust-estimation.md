> 출처 메모: GNC 논문(Yang·Antonante·Tzoumas·Carlone, RA-L 2020, arXiv 1909.08605v4)은 본문 5쪽 앞부분(서론~GNC 알고리즘 절, 점군 정합 결과)과 결론을 읽었다. 증명(보충 자료)과 형상 정렬(shape alignment)·포즈 그래프 실험의 세부는 읽지 않았다. TEASER 논문(Yang·Shi·Carlone, T-RO 2020, arXiv 2001.07715)은 초록, 서론, 불변 측정(TIM·TRIM)과 알고리즘 개요(VI장), TEASER++ 구현(X장), 실험(XI장) 일부를 읽었다. SDP 이완의 긴밀성 증명, 오차 한계 정리(15~16), DRS 인증기 알고리즘의 세부는 읽지 않았다. 아래 수치 실험은 직접 만든 장난감 모형(Python)이며 논문 수치의 재현이 아니다. 시간 비교는 구현 언어가 달라 논문 값과 비교할 수 없다.

## 문제

대응점 기반 정합·포즈 그래프에서 입력에는 **틀린 대응(이상치)** 이 섞인다. 특징 매칭은 70~90% 가 틀리기도 한다. 최소제곱은 이상치 한 개에도 끌려가고, RANSAC 은 최소 표본 수가 늘면 반복이 이상치 비율에 지수적으로 늘며(논문의 서술) 90% 부근에서 무너진다. 견고 비용(Huber, Geman-McClure, 절단 최소제곱)은 비볼록이라 **좋은 초기값이 필요**하다. [루프 클로저 이상치 거부(DCS·PCM)](/develop-wiki/knowledge/robotics/loop-closure-outlier-rejection/)가 SLAM 쪽 처방이라면, 여기서는 문제 종류에 상관없이 쓰는 두 방법을 본다.

## 해법 1: GNC (Graduated Non-Convexity)

### 아이디어

견고 비용 `ρ(r)` 대신 제어 변수 `μ` 를 가진 대리 함수 `ρ_μ(r)` 를 쓴다. `μ` 가 어느 값이면 `ρ_μ` 는 볼록(사실상 이차)이고, 극한에서 원래 `ρ` 로 돌아온다. 볼록한 쪽에서 시작해 `μ` 를 조금씩 바꾸며 직전 해를 다음 초기값으로 쓴다. 초기값이 필요 없다는 것이 장점이다.

논문의 두 예:

- **Geman-McClure**: `ρ_μ(r) = μ c̄² r² / (μ c̄² + r²)`. `μ → ∞` 면 이차, `μ = 1` 이면 원래 비용.
- **절단 최소제곱(TLS)**: `r² ≤ c̄²` 면 `r²`, 아니면 `c̄²` 로 잘라낸다. 대리 함수는 경계 근처를 매끄럽게 이은 구간 함수다.

### 가중치로 바꾸기 (Black-Rangarajan 쌍대성)

견고 비용 최소화는 가중치 `w_i ∈ [0, 1]` 를 넣은 `min Σ w_i r_i² + Φ(w_i)` 와 같다(`Φ` 는 "이상치 과정" 벌점). 변수와 가중치를 번갈아 푼다.

1. **변수 갱신**: 가중치 고정, `x = argmin Σ w_i r²(y_i, x)`. 이것이 곧 이상치 없는 문제의 **가중 최소제곱**이라서, 기존의 비최소 솔버(닫힌 해, SDP 등)를 그대로 쓴다. 이것이 GNC 의 일반성의 근거다.
2. **가중치 갱신**(닫힌 해, `r̂_i² = r²(y_i, x)`):
   - GM: `w_i = ( μ c̄² / (r̂_i² + μ c̄²) )²`
   - TLS: `w_i = 0` (`r̂_i² ≥ (μ+1)/μ · c̄²`), `1` (`r̂_i² ≤ μ/(μ+1) · c̄²`), 그 사이는 `c̄/r̂_i · √(μ(μ+1)) − μ`.

논문의 실무 지침: 첫 반복의 가중치는 모두 1. GM 은 `μ = 2 r²_max / c̄²` 에서 시작해 매 외부 반복 `μ ← μ/1.4`, `μ < 1` 에서 종료. TLS 는 `μ = c̄² / (2 r²_max − c̄²)` 에서 시작해 `μ ← 1.4 μ`, 가중 잔차 합이 수렴하면 종료. `c̄` 는 "내점이 가질 수 있는 최대 오차" 로 정한다. 외부 반복마다 변수·가중치 갱신을 한 번씩만 한다.

```ts
// GNC-TLS 골격 (solveWeighted: 가중 최소제곱 솔버, 문제마다 교체)
function gncTls(data: Datum[], cbar: number, solveWeighted: (d: Datum[], w: number[]) => Model) {
  let w = data.map(() => 1);
  let model = solveWeighted(data, w);
  const r2max = Math.max(...data.map((d) => d.residual2(model)));
  let mu = (cbar ** 2) / (2 * r2max - cbar ** 2);
  for (let it = 0; it < 100; it++) {
    model = solveWeighted(data, w);
    w = data.map((d) => {
      const r2 = d.residual2(model), c2 = cbar ** 2;
      if (r2 >= ((mu + 1) / mu) * c2) return 0;
      if (r2 <= (mu / (mu + 1)) * c2) return 1;
      return (cbar / Math.sqrt(r2)) * Math.sqrt(mu * (mu + 1)) - mu;
    });
    mu *= 1.4; // 수렴 판정은 생략
  }
  return { model, w };
}
```

### 논문이 보고한 것

- 점군 정합(Bunny, 대응 100 개, 내점 잡음 σ = 0.01)에서 RANSAC·GNC-GM·GNC-TLS·ADAPT 모두 **90% 이상치에서 무너졌고** 그 아래에서는 비슷한 정확도였다. 이상치 80% 평균 시간은 RANSAC 218 ms, GNC-GM 22 ms, GNC-TLS 23 ms 였다. 초록은 "70~80% 이상치에 견디고 RANSAC 을 능가한다" 고 요약하며, 전역 최적성은 보장할 수 없다고 직접 밝힌다.
- 점군 정합 한정으로 TEASER(전용 전역 솔버)가 더 견고했으나 큰 문제는 5분 넘게 걸려 확장되지 않는다고 서술한다.

### 직접 확인: 3차원 정합에서 최소제곱·GNC-TLS·RANSAC

Python(NumPy)으로 대응 100 개, σ = 0.01, 이상치는 균일 난수 점, `c̄ = 0.05` 로 설정해 회전 오차(도) 중앙값/최댓값을 30 회 시행했다. 가중 최소제곱은 Horn/Arun 식 SVD, RANSAC 은 3점 표본 1000 회다.

| 이상치 | 최소제곱 중앙값 | GNC-TLS 중앙/최대 | RANSAC1000 중앙/최대 |
| --- | --- | --- | --- |
| 30% | 11.3° | 0.27 / 0.4 | 0.27 / 0.4 |
| 70% | 41.3° | 0.41 / 0.6 | 0.41 / 0.6 |
| 80% | 66.3° | 0.47 / 169 | 0.49 / 1.0 |
| 90% | 123° | 50 / 172 | 3.8 / 166 |
| 95% | 95° | 100 / 176 | 110 / 174 |

70% 까지는 둘 다 정확하고, 80% 에서 GNC 는 가끔 완전히 틀린 해로 갔으며(최대 169°), 90% 에서 둘 다 무너졌다. 최소제곱은 30% 부터 이미 쓸 수 없다. 논문이 말한 "70~80% 한계, 전역 최적 비보장" 과 방향이 맞는다. 시간은 이 구현에서 GNC 1.3 ms, RANSAC 19 ms 로 비슷한 경향이나 절대값은 의미 없다.

## 해법 2: TEASER / TEASER++

점군 정합 `b_i = s R a_i + t + o_i + ε_i`(`o_i` 는 이상치일 때만 0 이 아님)를 TLS 비용으로 풀되, **스케일·회전·이동을 분리**해 차례로 푼다.

1. **불변 측정**. 두 점 쌍의 차 `b_j − b_i = s R (a_j − a_i) + …` 에서 이동 `t` 가 상쇄된다. 이것이 이동 불변 측정(TIM)이다. 길이(노름)를 취하면 회전까지 상쇄되어 스케일만 남는 TRIM 이 된다. 쌍은 최대 `N(N−1)/2` 개다.
2. **스케일**: TRIM 은 스칼라 측정이라 TLS 를 **다항 시간(적응형 투표)** 으로 정확히 푼다. 스케일과 안 맞는 쌍은 그래프에서 지운다.
3. **최대 클릭으로 이상치 제거**. 내점 쌍은 서로 일관되어 그래프에서 **클릭**(완전 부분그래프)을 이룬다(논문 정리 6: 내점 TIM 의 간선은 클릭을 이루고, 모든 내점을 포함하는 극대 클릭이 존재). 최대 클릭을 내점 집합으로 넘긴다. 이상치 비율이 높으면 그래프가 성기어 빨리 풀리는 경향이 있다고 논문은 말한다.
4. **회전**: TLS 회전 추정은 SDP 이완으로 풀 수 있고 이상치가 극단적이어도 이완이 **긴밀**함을 보였다고 한다(TEASER). 큰 SDP 는 느려서, **TEASER++** 는 회전을 GNC 로 풀고 결과가 전역 최적인지를 Douglas-Rachford 분할 기반 인증기로 **사후 확인**한다.
5. **이동**: 스케일과 회전을 알면 각 좌표를 TLS 스칼라 문제로 푼다(적응형 투표).

논문 초록·실험의 주장: 스케일이 알려졌을 때 **99% 이상 이상치**까지 견디고(대응 1000 개 Bunny 실험에서 TEASER, TEASER++, GORE 가 99% 까지 견딤), TEASER++ 는 일반 노트북에서 큰 이상치 비율도 10 ms 안에 푼다. 대응 없이 전수 쌍 가설을 넣는 문제에서도 ICP 보다 낫다고 한다. 회전 단계만 비교한 실험에서는 GNC 가 이상치 80% 미만에서 잘 되다 이후 실패하기 시작해, 앞 단계(스케일 + 최대 클릭)가 이상치를 줄여 GNC 의 짐을 덜어 주는 구조가 효과적이라고 설명한다.

### 직접 확인: 쌍 일관성 + 최대 클릭

대응 100 개에서 내점은 `B = A + 잡음(σ = 0.01)`, 이상치는 균일 난수 점이다. 쌍 거리 `| |a_i − a_j| − |b_i − b_j| | ≤ 4σ√2` 이면 간선을 두고(스케일 1 가정) 최대 클릭 크기를 구했다(NetworkX, 10 회).

| 이상치 | 진짜 내점 수 | 최대 클릭이 잡은 내점 |
| --- | --- | --- |
| 80% | 20 | 20/20 (5회 모두) |
| 90% | 10 | 10/10 (5회 모두) |
| 95% | 5 | 5 개 클릭이 나오지만 내점은 4, 1, 3 개 섞임 |
| 99% | 1 | 클릭 4~5 개, 내점 0 |

간선 밀도가 0.12~0.17 로 성기고, 내점이 극소수가 되면 **우연히 서로 일관된 이상치 클릭**이 같은 크기로 생겨 구분이 안 된다. 이 장난감은 거리 일관성만 쓰므로 TEASER 가 추가로 쓰는 정보(TIM 의 회전 일관성 등)가 없다. 논문이 99% 를 견딘다고 한 것은 대응 1000 개 규모 실험이고 이 모형과 직접 비교할 수 없다.

## 언제 쓰나

- **GNC**: 이상치 없는 버전의 솔버(가중 최소제곱)가 이미 있고 초기값을 믿기 어려울 때. 점군·메시 정합, 포즈 그래프, 자세 추정에 문제만 바꿔 끼운다. 반복 횟수가 이상치 비율과 거의 무관(논문 실험)해 시간이 예측 가능하다.
- **TEASER++**: 특징 매칭 대응에서 이상치가 매우 높고(수십%~99%), 해가 맞는지 **인증**이 필요하며 밀리초 단위 실행이 필요할 때. 학습 기반 키포인트 매칭 뒤의 정합 단계로 쓴다.
- 점진 SLAM 의 루프 클로저는 [PCM·DCS](/develop-wiki/knowledge/robotics/loop-closure-outlier-rejection/)가 쓰이고, 정합 이후 미세 조정은 [ICP·NDT](/develop-wiki/knowledge/robotics/icp-ndt-scan-matching/)가 맡는다.

## 주의/비용

- **GNC 는 전역 최적을 보장하지 않는다.** 논문 초록이 직접 말한다. 위 실험에서 80% 에서도 가끔 완전 실패했다. 정확성이 중요하면 결과를 검증 단계(내점 수, 잔차 분포)로 걸러야 한다.
- **`c̄` 선택.** 내점의 최대 오차를 알아야 한다. 너무 작으면 내점을 버리고 너무 크면 이상치가 들어온다. 잡음 모델이 틀리면 둘 다 흔들린다.
- **TEASER 전제.** 대응이 있고 모델이 상사 변환(스케일·회전·이동) 한 가지라는 전제다. 최대 클릭은 최악 지수 시간이며, 대응 수가 매우 많으면 O(N²) 쌍 그래프가 메모리를 먹는다(대응 수는 사전 필터링).
- **인증은 가정 아래에서의 인증이다.** 논문의 오차 한계·최적성 인증은 잡음 상한과 모델 가정에 의존한다. 이 노트에서는 그 정리들을 읽지 않았다.
- **SDP 버전(TEASER)은 느리다.** 논문도 실시간 로봇에는 적합하지 않다고 하고, 그래서 TEASER++ 를 만들었다.
