## 문제

[M/M/c 노트](/develop-wiki/knowledge/performance/queueing-theory-utilization-latency/)는 사용률이 오르면 지연이 비선형으로 오른다고 했다. 그 공식은 서비스 시간이 **지수분포**라고 가정한다. 현실의 서비스 시간은 캐시 적중이면 1 ms, 미스면 100 ms 처럼 꼬리가 길다. 같은 사용률 70% 에서 어떤 서비스는 쾌적하고 어떤 서비스는 지연이 튀는 이유가 여기 있다.

## 모델: M/G/1

도착은 포아송(λ), 서비스 시간 S 는 **임의 분포(General)**, 서버 하나, 무한 FIFO 대기열. 필요한 것은 평균 `E[S]` 와 분산 `Var(S)` 뿐이다.

- 사용률 ρ = λ·E[S] (< 1 이어야 안정)
- 변동 계수 제곱 SCV c² = Var(S) / E[S]²

### Pollaczek–Khinchine 공식

위키백과의 정리를 근거로 한다. 평균 시스템 내 개수:

> L = ρ + (ρ² + λ²·Var(S)) / (2(1−ρ))

이를 `E[S²] = Var(S) + E[S]²` 로 바꾸면 **평균 대기 시간(큐에서만)** 은

> Wq = λ·E[S²] / (2(1−ρ)) = ρ · (1 + c²) / (2(1−ρ)) · E[S]

(위 변형은 해당 페이지가 직접 쓴 것이 아니라 대수 변환으로 얻은 것이고, 아래 시뮬레이션으로 값이 맞는지 확인했다.) 체류 시간 W = Wq + E[S].

요점:

- **분산이 대기에 직접 곱해진다**: Wq 가 (1 + c²)/2 에 비례한다. 지수분포(c²=1)면 인수가 1 이라 M/M/1 의 ρ/(1−ρ)·E[S] 와 같다.
- 서비스 시간이 일정(c²=0)이면 지수일 때의 **절반**이다(M/D/1).
- 사용률 항 1/(1−ρ) 은 그대로라 변동성과 사용률이 **곱으로** 나쁘게 작용한다.

## 직접 실행으로 확인

서비스 평균을 1 로 정규화하고, 300만 건(앞 10% 버림, 시드 고정)을 돌렸다. 로그정규 분포로 c² 를 키웠다. Wq 는 서비스 시간 단위, p99 는 체류 시간(대기+서비스) 99번째 백분위.

| 분포 | ρ | 이론 Wq | 시뮬 Wq | 시뮬 p99 |
| --- | --- | --- | --- | --- |
| 고정 (c²=0) | 0.5 | 0.50 | 0.50 | 4.4 |
| 지수 (c²=1) | 0.5 | 1.00 | 0.99 | 9.2 |
| 로그정규 (c²=4) | 0.5 | 2.50 | 2.49 | 31.1 |
| 로그정규 (c²=16) | 0.5 | 8.50 | 8.18 | 122.0 |
| 고정 | 0.8 | 2.00 | 2.00 | 11.4 |
| 지수 | 0.8 | 4.00 | 4.01 | 23.0 |
| 로그정규 (c²=4) | 0.8 | 10.00 | 10.16 | 78.3 |
| 로그정규 (c²=16) | 0.8 | 34.00 | 34.31 | 344.0 |
| 고정 | 0.9 | 4.50 | 4.50 | 23.0 |
| 지수 | 0.9 | 9.00 | 9.09 | 47.8 |
| 로그정규 (c²=4) | 0.9 | 22.50 | 22.58 | 132.1 |
| 로그정규 (c²=16) | 0.9 | 76.50 | 80.42 | 636.1 |

- 이론과 시뮬이 일치한다(c²=16, ρ=0.9 는 꼬리가 무거워 표본 오차가 커서 5% 가량 어긋났다).
- **ρ=0.5 에서도 c²=16 이면 평균 대기가 8.5배 서비스 시간**이다. 사용률만 보고 "여유 있다"고 판단하면 틀린다.
- p99 는 평균 대기보다 더 크게 벌어진다. 평균 대기는 P-K 로 구하지만 **분위수는 P-K 가 알려 주지 않는다**(이 노트의 p99 는 시뮬레이션 값이다).

```ts
// 이론 평균 대기 (서비스 시간 단위, E[S]=1): rho = 사용률, scv = Var(S)/E[S]²
const wqPK = (rho: number, scv: number) => (rho * (1 + scv)) / (2 * (1 - rho));
// wqPK(0.8, 0)=2, wqPK(0.8, 1)=4, wqPK(0.8, 16)=34
```

## 실무에서의 의미

- **같은 사용률 목표라도 변동성이 크면 목표를 낮춘다.** SCV 를 측정하면 대기를 예측할 수 있다. 서비스 시간의 평균·분산은 트레이싱/히스토그램에서 얻는다 → [프로파일링](/develop-wiki/knowledge/performance/profiling/).
- **변동성을 줄이는 것이 사용률을 낮추는 것만큼 효과적일 수 있다.** 느린 요청을 별도 풀로 분리하거나 상한 타임아웃을 둬 꼬리를 자르고, 배치 크기를 균일하게 한다. 격리 풀은 [벌크헤드](/develop-wiki/knowledge/performance/bulkhead/).
- 느린 쿼리 하나가 뒤의 빠른 요청까지 막는 현상(head-of-line blocking)이 이 공식의 직관이다. 긴 작업과 짧은 작업을 같은 큐에 섞지 않는다.
- 서버를 여러 대로 늘리면 대기가 줄지만, 이 노트의 공식은 **서버 1대**에 대한 것이다. 다중 서버의 변동성 효과는 근사식이 따로 있고 여기서 검증하지 않았다.

## 언제 쓰나

- 용량 계획에서 "사용률 몇 %까지"를 정할 때 서비스 시간 분포를 같이 본다.
- p99 가 평균과 크게 벌어지는 원인을 큐잉으로 설명해야 할 때.
- 작업 크기가 매우 불균등한 워커 큐(이미지 변환, 리포트 생성).

## 주의 (비용)

- **도착이 포아송이라는 가정이 있다.** 실제 트래픽은 버스트라 더 나쁘다. 이 공식은 하한에 가깝다.
- 서비스 시간이 요청 간 **독립**이라는 가정도 있다. 부하가 높을 때 서비스 시간이 함께 늘면(락 경합, GC) 모델이 낙관적이다.
- 이론 평균은 `E[S²]` 가 유한해야 성립한다. 꼬리가 매우 무거운 분포(분산이 없는 경우)에서는 대기 평균이 무한이다.
- 평균 대기 공식은 분위수·최악 지연을 말하지 않는다. SLO 가 p99 이면 시뮬레이션이나 측정이 필요하다.
- 시뮬레이션 한계: 단일 서버, FIFO, 정상 상태. 과부하(ρ ≥ 1)나 재시도는 다루지 않는다 → [메타안정 장애](/develop-wiki/knowledge/performance/metastable-failures-retry-storm/).

## 검증 범위

위키백과의 P-K 공식 정리를 확인하고(원 논문 Pollaczek 1930, Khinchine 1932 와 교재 Kleinrock, Harchol-Balter 는 읽지 못했다), 대수 변환과 숫자를 시뮬레이션으로 검증했다. Wq 의 변환식은 위키백과 페이지가 직접 쓰지는 않았다.
