> 출처 메모: 직접 읽은 것은 Hannaford·Ryu, "Time Domain Passivity Control of Haptic Interfaces" 의 **저자 원고**다. UW BioRobotics Lab 공개 목록(Rep151, 웹 아카이브 사본)에 있는 2000-05-16 자 "IEEE Transactions on Robotics and Automation 에 수정 재투고" 판으로, 2002 년 출판본(TRA 18(1):1–10)과 문구·수치가 다를 수 있다. 같은 목록의 ICRA 2001 학회판(Rep138)은 초록만 대조했다. 아래 식 번호는 저자 원고 기준이다. 주파수 영역 한계식(Colgate·Schenkel)은 [수동성과 접촉 안정성](/develop-wiki/knowledge/robotics/passivity-contact-stability/)에서 다뤘다.

## 문제

수동성은 "들어온 에너지보다 많이 내놓지 않는다" 는 성질이다. 사람 조작자를 수동으로 볼 수 있으면, 장치·제어기·가상 환경이 모두 수동일 때 전체가 안정하다고 결론 낼 수 있다.

- 고정 파라미터 설계(가상 커플링, Colgate·Schenkel 한계)는 최악 조건을 가정해 **보수적**이다. 늘 큰 감쇠를 넣어 성능을 깎는다.
- 실제 시스템은 설계상 수동이어도 능동이 될 수 있다. 원고가 드는 원인: 수치 적분 지연, 양자화, 이산 제어와 연속 장치·사람의 상호작용("energy leak"). 여기에 비선형 가상 환경, 느린 시뮬레이션이 더해진다.
- 이런 경우 선형 모델 기반 해석이 어렵다.

## 해법

### 수동성의 시간 영역 정의

1포트 `N` 이 초기 에너지 `E(0)` 일 때 모든 `t ≥ 0` 에서 `∫₀ᵗ f(τ)v(τ)dτ + E(0) ≥ 0` 이면 수동이다(식 1). 힘·속도 부호는 곱이 양수일 때 에너지가 포트로 **들어가는** 방향으로 정한다. M 포트는 각 포트의 `f·v` 를 더한다(식 2).

### 수동성 관측기 (PO)

샘플 주기 `ΔT` 로 측정한 힘·속도를 누적한다(식 3):

```
E_obsv(n) = ΔT · Σ_{k=0..n} f(k) v(k)
```

- `E_obsv(n) ≥ 0` 이 계속 유지되면 소산, 어느 순간 음수면 그만큼(`−E_obsv`) 에너지를 만든 것이다.
- 전제: 샘플링이 장치·사람·환경 동역학보다 충분히 빨라 샘플 사이 변화가 작아야 한다. 원고 시스템은 1000 Hz 로, 의미 있는 최고 모드의 10 배 이상이라고 한다.
- 여러 블록을 묶은 네트워크도 **열린 포트**의 `f·v` 만으로 전체 에너지 수지를 구할 수 있다(정리 1, 텔레겐 정리 근거). 블록마다 PO 를 달면 어느 블록이 능동인지 찾을 수 있다.

### 수동성 제어기 (PC)

PO 가 음수가 되면 그 에너지를 정확히 소산시키는 **가변 감쇠기** `f = α v` 를 넣는다.

- 인과성에 따라 배치가 다르다. 임피던스 인과(속도 입력, 힘 출력)면 **직렬**(속도 보존) PC, 어드미턴스 인과(힘 입력, 속도 출력)면 **병렬**(힘 보존) PC.
- 직렬 PC 의 한 샘플 절차(식 16):
  1. 속도 `v₂(n) = v₁(n)` 을 입력받는다.
  2. 가상 환경이 힘 `f₂(n)` 을 계산한다.
  3. `E_obsv(n) = E_obsv(n−1) + f₂(n)v₂(n)ΔT + α(n−1)v₂(n−1)²ΔT`
  4. `E_obsv(n) < 0` 이면 `α(n) = −E_obsv(n) / (ΔT · v₂(n)²)`, 아니면 `α(n) = 0`.
  5. 출력 힘 `f₁(n) = f₂(n) + α(n)v₂(n)`.
- 이렇게 하면 열린 포트의 누적 에너지가 모든 `n` 에서 0 이상이 된다(식 19).
- 바깥 요소(사람 손, 장치 마찰)의 소산을 믿을 수 있으면 기준을 0 대신 음수로 둘 수 있다(식 24: 임피던스 인과에서 `−β Σ v₁²`). 원고 실험은 `b = 35 N·s/m` 를 가정했다.

```ts
// 직렬 수동성 제어기 (원고 식 16 의 구조). 임피던스 인과: 속도 입력, 힘 출력
export function makeSeriesPC(dT: number, alphaMax = Infinity, vEps = 1e-4) {
  let E = 0, prevAlpha = 0, prevV = 0;
  return (v: number, fEnv: number): number => {
    E += fEnv * v * dT + prevAlpha * prevV * prevV * dT;   // PO 갱신
    let alpha = 0;
    if (E < 0 && Math.abs(v) > vEps) alpha = Math.min(-E / (dT * v * v), alphaMax);
    prevAlpha = alpha; prevV = v;
    return fEnv + alpha * v;                                // 장치로 보낼 힘
  };
}
```

`alphaMax` 와 `vEps` 는 원고 3장이 말한 포화·잡음 문제를 다루려고 내가 넣은 인자다. 이렇게 제한하면 한 샘플에 다 소산하지 못한 에너지가 PO 에 남아 다음 샘플로 넘어간다(원고도 같은 결과를 설명한다).

## 원고가 보고한 것

- **시뮬레이션 1**: 1차 벌칙형 스프링-댐퍼 벽, 1000 Hz, 사인파 속도로 찌름. `k = 710 N/m, b = 50 N·s/m` 면 PO 가 (단조는 아니지만) 증가. `b = −50` 이면 튕길 때마다 PO 가 더 음수. PC 를 켜면 PO 가 0 이상으로 유지.
- **시뮬레이션 2**: 사람·장치·PC·가상 환경 모델, 환경 강성 30 kN/m, 66.67 Hz(15 ms) 로 느리게 갱신. PC 없이는 접촉이 크게 불안정, PC 를 켜면 약 세 번 튕긴 뒤(약 0.5 s) 안정. 첫 튕김의 PC 힘은 약 350 N.
- **실험(Excalibur 3축 햅틱 장치, 1000 Hz, 최대 200 N)**:
  - 강성 90 kN/m 접촉: PC 없이 진동이 계속. PC 를 켜면 약 6 번 튕긴 뒤 안정, PC 힘 40 N 미만. 첫 튕김은 수동, 이후 작은 튕김들이 능동이었다.
  - PC 힘을 ±20 N 으로 제한해도 결과가 거의 같았다.
  - 가상 환경을 66.67 Hz 로 늦추고 강성 30 kN/m: PC 없이 힘 펄스가 200 N 까지, PC 를 켜면 한 번의 튕김 안에 안정.
  - PO 를 여러 지점에 달아 보니 능동 성분의 주원인은 **쿨롱 마찰 보상** 모듈이었다. 원고는 이 보상 항이 수학적으로 능동임을 보인다(식 27).
- 초록은 "강성 > 100 N/mm 또는 지연 15 ms 에서 안정" 이라고 쓰지만, 원고 본문의 강성 실험 값은 90 kN/m(= 90 N/mm)다. 2002 출판본의 **초록**(출판사 초록, OpenAlex 경유로 2026-11-19 대조)도 "> 100 N/mm 또는 15 ms" 로 원고와 같다. 출판본 **본문**의 실험 강성 값은 본문을 구하지 못해 여전히 미확인이다.

### 직접 확인: 음의 감쇠 벽에서 PO/PC

원고 시뮬레이션 1 을 흉내 내 Node.js 로 돌렸다. 1000 Hz, 벽 `k = 710 N/m`, 속도 `0.1 cos(2π·1·t) m/s` 로 4 초, 초기 위치 `x(0) = −0.01 m`, 벽은 `x > 0` 에서만 힘 `k x + b v` 를 낸다. 매 샘플 위치를 먼저 `x += v·ΔT` 로 갱신한 뒤 힘을 계산했고, PC 는 위 `makeSeriesPC` 를 그대로 썼다. 내 설정이며 원고의 궤적 진폭·초기 위치는 알 수 없다.

| 경우 | 4 초 후 PO (J) | PO 최솟값 (J) | PC 최대 힘 (N) |
| --- | --- | --- | --- |
| `b = +50` | 0.132 | 0 | — |
| `b = −50`, PC 없음 | −0.130 | −0.130 | — |
| `b = −50`, PC 있음 | 0 | 0 | 5.3 |

`x(0) = 0` 으로 두면 벽 안에 머무는 시간이 길어져 값이 커진다(PO 0.506 / −0.499 J, PC 최대 11.9 N). 방향은 원고와 같다. 이 모형은 속도를 강제로 주므로 "불안정해서 발산" 하는 장면은 나오지 않고, 에너지 수지만 확인한 것이다. PC 최대 힘은 속도가 0 근처일 때 `α = −E/(ΔT v²)` 가 커지면서 생겼다.

## 언제 쓰나

- 햅틱 장치, 양방향 원격 조작처럼 사람과 에너지를 주고받는 루프에서, 가상 환경·통신 지연·보상 항 때문에 능동 동작이 의심될 때.
- 환경이 비선형이거나 갱신 주기가 불규칙해서 [주파수 영역 수동성 한계식](/develop-wiki/knowledge/robotics/passivity-contact-stability/)을 쓰기 어려운 경우.
- 고정 감쇠로 늘 성능을 깎는 대신 "필요할 때 필요한 만큼만" 감쇠하고 싶을 때. 원고는 저장 요소를 모델링할 필요가 없고 소산만 알면 된다고 강조한다.
- 진단 도구로: PO 만 달아서 어느 모듈이 에너지를 만드는지 찾는다(원고의 마찰 보상 사례).

## 주의/비용

- **저속에서 힘이 튄다.** 직렬 PC 는 `α = −E/(ΔT v²)` 라 속도가 작을 때 큰 힘이 나오고 속도 추정 잡음을 키운다. 원고 실험에서도 저속 구간에 PC 출력이 잡음처럼 흔들려 사용자가 진동을 느끼고 들었다고 한다. 병렬 PC 는 힘이 작을 때 같은 문제가 있다.
- **작동기 포화.** 소산에 필요한 힘이 작동기 한계를 넘을 수 있다. 제한하면 남은 에너지가 다음 샘플로 미뤄진다.
- **에너지 저금 문제.** 소산이 큰 곳에서 오래 상호작용하면 PO 가 큰 양수를 쌓는다. 그 뒤 능동인 곳으로 가면 쌓인 만큼 능동 동작을 허용한 뒤에야 PC 가 작동한다. 이론적으로 경계는 있지만 실무에서는 원치 않는 진동이 생길 수 있다. 원고는 PO 재설정 휴리스틱을 향후 과제로 남겼다.
- **수동성은 충분조건**이다. 사람 조작자를 수동으로 가정하는 근거는 경험·일부 증거(Hogan) 수준이라고 원고 스스로 쓴다.
- 샘플링이 동역학보다 충분히 빨라야 이산 합이 실제 에너지를 대표한다. 느린 루프에서는 PO 자체가 부정확해진다.
- 바깥 소산 `β` 를 크게 잡으면 성능은 좋아지지만 가정이 틀리면 보장이 깨진다.
